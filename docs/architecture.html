MeetClient (WebRTC Peer Connection Engine)

meet-client/src/meet/MeetClient.ts
WebRTC Core

💡 Plain-English Analogy & Role

The mission controller of the bot. It creates the WebRTC peer connection with 3 audio receivers, data channels, and 3 video receivers, exchanges SDP with Google, and manages the live WebRTC connection.

🔄 Data Inputs & Outputs

Inbound: Meeting Space ID & OAuth Token ➔ Outbound: Established WebRTC Media Connection & Audio Tracks.

💻 Key Code Snippet / Implementation

// Strict SDP transceiver order required by Google Meet:
// 1. Audio (3 recvonly) -> 2. DataChannels -> 3. Video (3 recvonly)
for (let i = 0; i < 3; i++) {
  this.pc.addTransceiver('audio', { direction: 'recvonly' });
}

Key Scalability Advantages Over Legacy Screen-Recording Bots

  • No Video Rendering Overhead: The bot does not render or composite heavy video canvases. It pulls raw audio tracks directly from Google's SFU.
  • Client-Side DSP Resampling: Converting Float32 to 16kHz Linear PCM runs in client threads, keeping the central API server completely free of audio transcoding loads.
  • Stateless Containerized Runners: If a meeting disconnects, its container terminates cleanly without affecting any other running meeting instances in the cluster.
  • Redis Pub/Sub WebSocket Multiplexing: Transcripts are published to Redis, allowing thousands of dashboard users to view live streams across distributed API nodes.
